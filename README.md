Assignment 2: Detecting Emotions with ML Algorithms

Course 5ARE0 Data Analysis and Learning Methods (TU/e), October 2026. Authors: Ewen Pouliquen, Mateusz Lotko, Solomos Solomou.

The project compares emotion-recognition models on two datasets, FER2013 (in-the-wild, 48x48 grayscale) and KDEF (posed, frontal studio photographs), and studies how well a model transfers between them. The written analysis is in report.pdf; this repository contains the code and the saved results behind it. AI use is documented in report.

Contents
Task	File	What it does	Main outputs
1. FER2013 baseline	task1_fer_teammate.ipynb	HOG, dlib landmarks and PCA features with LogReg, SVM and Random Forest; hyperparameters chosen on PublicTest, final numbers on PrivateTest	results/task1_*.csv, models/fer_*.pkl
2. KDEF study	task2_kdef_teammate.ipynb	Same features and classifiers on frontal KDEF images with a subject-independent split and subject-grouped cross-validation	results/task2_kdef_results.csv, models/kdef_*.pkl
3. Cross-dataset generalization	task3_cross_dataset.ipynb	Re-fits the Task 2 configurations on KDEF and evaluates them directly on FER2013; domain-shift analysis	results/task3_*.csv, figures/task3/
4. Explainable fuzzy classifier	task4_fuzzy_classifier.ipynb	Six dlib-landmark geometric features and a hand-written fuzzy rule base on KDEF	auxFiles/fuzzy_rules_frozen.json
5. Creative challenge	task5_creative_challenge.ipynb	Improvements on the FER baseline (regularization, class weighting, feature selection, KDEF-selected geometry features)	models/task5_*.pkl
6. Real-time demo	task6_webcam_demo.py	Webcam, video or single-image demo with the saved Task 5 model	none

Shared code is in src/: features.py (HOG, landmark and pixel features, label mapping), preprocess.py (course KDEF preprocessing), emotion_features.py and teammate_features.py (feature extractors used by Tasks 5 and 6).

Running order
task1_fer_teammate.ipynb (writes results/task1_*.csv and the FER models)
task2_kdef_teammate.ipynb (writes results/task2_kdef_results.csv and the KDEF models)
task3_cross_dataset.ipynb (needs results/task2_kdef_results.csv; picks the best Task 2 configuration by cross-validation macro-F1)
task4_fuzzy_classifier.ipynb (independent of Tasks 1 to 3; needs KDEF and the subject split)
task5_creative_challenge.ipynb (needs the Task 1 HOG model and cached features)
Webcam demo: python task6_webcam_demo.py (press q to quit). Options: --image path for one cropped face, --video path, --camera index, --smooth N (majority vote over N frames), --model path (default models/task5_best_model.pkl), --lecturer (course reference model).

The first run of a notebook is slow because features are extracted and cached (data/features/, data/kdef_preprocessed_fer_format.pkl). Task 3 and Task 4 notebooks are saved with their outputs, so the numbers in the report can be read without rerunning them.

Notes
The KDEF subject split is by person (56 train / 14 test subjects), so no person appears in both sets.
The FER2013 PrivateTest split is used only for final numbers; model selection uses PublicTest (FER) or subject-grouped cross-validation (KDEF).
